# จากคลิปจริง → เฟรมภาพ → ภาพเคลื่อนไหวตามการเลื่อน

คู่มือนี้สำหรับฝ่ายฝึกวิชาชีพผู้ต้องขัง ทัณฑสถานบำบัดพิเศษกลาง อธิบายวิธีนำคลิปหรือชุดเฟรมที่มีอยู่แล้วเข้าสู่หน้าแรก

หน้าแรกมีฉากที่ขับเคลื่อนด้วยการเลื่อนสองฉาก แต่ละฉากใช้ชุดเฟรมของตัวเอง

| ชุด | ตำแหน่ง | บทบาท |
| --- | --- | --- |
| `hero` | `public/frames/hero/` | ฉากเปิด เลื่อนแล้วภาพเดินหน้าทีละเฟรม |
| `reveal` | `public/frames/reveal/` | ฉากถัดมา จอเปิดออกจากกึ่งกลางแล้วเผยคลิป |

**ทั้งสองชุดไม่บังคับ** หากยังไม่ได้นำเข้า หน้าแรกจะแสดงองค์ประกอบนิ่งที่ออกแบบไว้แทน ความสูงของหน้าไม่เปลี่ยน และไม่มีการเรียกไฟล์เฟรมใด ๆ

## 1. มีชุดเฟรมอยู่แล้ว (เช่น `frames/merged_20s_frames`)

นำเข้าได้ทันทีจากโฟลเดอร์ ไม่ต้องบีบเป็น ZIP และไม่ต้องเปลี่ยนชื่อไฟล์ก่อน

```powershell
pnpm frames:import "frames\merged_20s_frames" --set hero --encode
pnpm frames:import "frames\clip2_frames" --set reveal --encode
```

ตัวนำเข้าจะ

1. อ่านไฟล์ PNG หรือ JPEG ทั้งหมดในโฟลเดอร์ เรียงตามลำดับตัวเลขในชื่อไฟล์ (`shot_9` มาก่อน `shot_10`)
2. **เลือกให้เหลือ 150 เฟรมพอดี** โดยกระจายให้ทั่วทั้งชุด เก็บเฟรมแรกและเฟรมสุดท้ายไว้เสมอ คลิป 20 วินาทีที่ 30 fps มีราว 600 ภาพ จึงถูกเลือกทุก ๆ 4 ภาพ
3. ตรวจโครงสร้างไฟล์ภาพและขนาดภาพที่ต้องเท่ากันทุกเฟรม
4. คัดลอกข้อมูลภาพต้นฉบับโดยไม่แก้ไข เปลี่ยนเพียงชื่อไฟล์เป็น `frame-001` ถึง `frame-150`
5. เขียน `manifest.json` เป็นขั้นตอนสุดท้าย หากการตรวจไม่ผ่าน ชุดเฟรมเดิมจะยังอยู่ครบ

ต้องการจำนวนอื่นให้ใช้ `--max` เช่น `--max 240` สำหรับภาพที่ลื่นขึ้นแต่ดาวน์โหลดหนักขึ้น หรือ `--max 90` สำหรับชุดที่เบากว่า รองรับตั้งแต่ 8 ถึง 600 เฟรม

### ขนาดไฟล์ที่ผู้ชมต้องดาวน์โหลด

ภาพที่ส่งออกจากกล้องหรือโปรแกรมตัดต่อมักใหญ่เกินกว่าที่เว็บต้องใช้มาก ชุด `merged_20s_frames` มีขนาดรวม 139 MB เมื่อเลือกมา 150 เฟรม ซึ่งมากเกินกว่าที่ภาพจะตามการเลื่อนทัน

`--encode` จะบีบภาพใหม่สำหรับใช้งานบนเว็บ (JPEG คุณภาพ 76 กว้างไม่เกิน 1280 พิกเซล ปรับได้ด้วย `--quality` และ `--width`) ชุดจริงลดจาก **139 MB เหลือ 17.3 MB** โดยไม่เปลี่ยนไฟล์ต้นฉบับใน `frames/` แต่อย่างใด

หากไม่ใส่ `--encode` ตัวนำเข้าจะคัดลอกข้อมูลภาพต้นฉบับไว้เหมือนเดิม และถ้าชุดนั้นรวมกันเกิน 40 MB จะหยุดพร้อมบอกวิธีลดขนาด ต้องการนำเข้าไฟล์ใหญ่ตามเดิมจริง ๆ ให้ใช้ `--allow-large`

## 2. เริ่มจากคลิปวิดีโอ

ถ้ามีเพียงไฟล์วิดีโอ ให้แปลงเป็นชุดเฟรมก่อนด้วย FFmpeg ผ่านตัวช่วยเดิม

```powershell
pnpm frames:make "E:\video\hero.mp4" --start 2 --duration 8
pnpm frames:import
```

`frames:make` ต้องใช้ Python 3.9 ขึ้นไปพร้อม FFmpeg และ FFprobe หาก FFmpeg ไม่อยู่ใน PATH ให้ระบุด้วย `--ffmpeg "H:\New folder\ffmpeg\bin\ffmpeg.exe"` ผลลัพธ์คือ `public/frames/_150.zip` ซึ่ง `frames:import` อ่านได้โดยตรง

### ถ่ายคลิปใหม่

1. ถ่ายแนวนอน 16:9 ที่ 1080p / 30 fps ใช้ขาตั้งหรือพยุงกล้องให้มั่นคง
2. ใช้ฉากหลังเข้มเรียบ ให้ฉากกินพื้นที่ถึงขอบภาพ
3. ใช้แสงนุ่มโทนอุ่นจากด้านข้าง ให้เห็นผิววัสดุและรายละเอียดของงาน โดยยังรักษาสีจริงของผลงาน
4. เผื่อพื้นที่ว่างรอบชิ้นงานสำหรับข้อความ และวางรายละเอียดสำคัญใกล้กึ่งกลาง เพราะจอมือถือจะตัดด้านข้างออก
5. เคลื่อนกล้องช้าและสม่ำเสมอ ภาพจะย้อนกลับเมื่อผู้ชมเลื่อนขึ้น จึงควรดูเป็นธรรมชาติทั้งสองทิศทาง
6. ไม่ใส่ข้อความ โลโก้ เส้นขอบ ทรานซิชัน หรือการตัดสลับหลายช็อตลงในคลิป

สำหรับแนวทางภาพต้น–ภาพปลายด้วย AI ดู [CINEMATIC-PROMPTS.md](CINEMATIC-PROMPTS.md)

## 3. ตรวจผลบนหน้าเว็บ

```powershell
pnpm dev
```

เปิด [localhost:3000](http://localhost:3000) แล้วตรวจตามนี้

1. ฉากเปิดเริ่มที่เฟรม 001 เมื่อเลื่อนจนสุดช่วงที่ตรึงไว้ต้องถึงเฟรม 150
2. เลื่อนช้า เลื่อนเร็ว และเลื่อนย้อนกลับ ภาพต้องตามตำแหน่งเลื่อนและค่อย ๆ เข้าหาเฟรมเป้าหมาย
3. ช่วงท้ายของฉากเปิด ภาพต้องค่อย ๆ เบลอและจางเข้าหาฉากถัดไป ไม่ตัดฉับ
4. ฉากถัดมาต้องเริ่มจากช่องแสงบาง ๆ กลางจอ แล้วเปิดออกจากกึ่งกลางจนเต็มจอ ข้อความอยู่ด้านขวา
5. ย่อหน้าต่างและเปิดด้วยมือถือ ภาพต้องเต็มพื้นที่ เมนู ข้อความ และปุ่มยังอ่านและกดได้
6. เปิด Reduce Motion ในระบบ ทั้งสองฉากต้องอยู่นิ่ง ฉากถัดมาต้องเปิดค้างไว้ให้อ่านเนื้อหาได้ และต้องดาวน์โหลดเพียงเฟรมแรกเฟรมเดียว

ตรวจอัตโนมัติในเบราว์เซอร์จริงด้วยเฟรมทดสอบในหน่วยความจำ (ไม่แตะฐานข้อมูลและไฟล์จริง)

```powershell
node scripts/verify-scroll-sequence.mjs
```

สำหรับ production ให้นำเข้าก่อน `pnpm build` แล้วรวม `public/frames` ในการส่งขึ้นเซิร์ฟเวอร์ด้วย การนำเข้าในเครื่องยังไม่ใช่การ deploy เว็บไซต์

## หากติดปัญหา

| อาการ | วิธีแก้ |
| --- | --- |
| `Frames missing` | ตรวจเส้นทางโฟลเดอร์หรือ ZIP ให้ตรงกับไฟล์จริง |
| `over the 40 MB budget` | เพิ่ม `--encode` หรือลด `--max` หรือใช้ `--allow-large` ถ้าตั้งใจ |
| `--encode needs Node.js on PATH` | เปิด Terminal ที่มี Node.js เวอร์ชัน 22 ขึ้นไปตาม SETUP.md |
| `Found N frames; at least 8 needed` | โฟลเดอร์มีภาพน้อยเกินไป หรือไฟล์ไม่ใช่ PNG/JPEG |
| `Mismatched dimensions` | ทุกเฟรมต้องมีขนาดเท่ากัน ให้ส่งออกใหม่จากคลิปเดียว |
| `Mixed formats` | อย่าปน PNG กับ JPEG ในชุดเดียวกัน |
| `FFmpeg not found` | เพิ่ม FFmpeg ลง PATH หรือใช้ `--ffmpeg` พร้อมเส้นทางเต็ม |
| ยังเห็นองค์ประกอบนิ่ง | ตรวจว่ามี `manifest.json` ในโฟลเดอร์ของชุดนั้น แล้วรีสตาร์ต `pnpm dev` และตรวจ Reduce Motion ด้วย |
| โหลดช้าบนมือถือ | นำเข้าใหม่ด้วย `--max 90` หรือย่อความกว้างของภาพต้นทาง |

รายละเอียด FFmpeg อ้างอิง [เอกสาร FFmpeg](https://ffmpeg.org/ffmpeg-all.html) อัตราเฟรมของการแปลงใช้เพื่อเตรียมไฟล์เท่านั้น การเล่นบนหน้าเว็บขับเคลื่อนด้วยตำแหน่ง scroll
