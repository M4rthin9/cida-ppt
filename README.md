# ฝ่ายฝึกวิชาชีพผู้ต้องขัง · cida-ppt

เว็บไซต์ผลงานและการฝึกวิชาชีพของ **ทัณฑสถานบำบัดพิเศษกลาง** พร้อม CMS ที่ใช้ฐานข้อมูลจริง

**ฝึกอาชีพ สร้างทักษะ สร้างคุณค่า สร้างโอกาสใหม่**

## สิ่งที่ทำได้

- หน้าแรกเชิงบรรณาธิการ ภาษาไทย แสดงหมวดและสินค้าแนะนำจากฐานข้อมูล
- แคตตาล็อก ค้นหา กรอง เรียงลำดับ และแบ่งหน้า พร้อม URL ของหมวดและสินค้าแต่ละชิ้น
- ราคา 5 รูปแบบ: ราคาคงที่ / เริ่มต้น / สอบถามราคา / รับสั่งทำ / จัดแสดงผลงาน
- CMS `/admin`: จัดการหมวด สินค้า ภาพ ข่าวฝึกวิชาชีพ ข้อความสอบถาม และการตั้งค่า
- สินค้า: สร้าง แก้ไข ทำสำเนา เผยแพร่ ซ่อน เก็บถาวร กู้คืน ย้ายหมวด และจัดการหลายรายการ
- หมวด: เปิด/ปิด เผยแพร่/ซ่อน เรียงลำดับ เปลี่ยนภาพ/ไอคอน/SEO; การลบหมวดที่มีสินค้าต้องเลือกหมวดปลายทาง
- อัปโหลด JPEG / PNG / WebP ลากวาง จัดลำดับ เลือกภาพปก และเก็บไฟล์ต้นฉบับโดยไม่แก้ไขชิ้นงาน
- Auth.js + Argon2id; ผู้ดูแลสูงสุด (`owner`) และผู้แก้ไข (`editor`); ตรวจสิทธิ์ที่เซิร์ฟเวอร์และบันทึก audit
- สอบถามสินค้าผ่าน LINE พร้อมชื่อ SKU และ URL; แบบติดต่อบันทึกในฐานข้อมูลแม้ไม่มี SMTP

ไม่มีระบบจัดการผู้ต้องขัง เยี่ยมญาติ จดหมาย วินัย หรือชำระเงิน

## เทคโนโลยี

ต่อยอดแอปเดิม: Next.js 15 App Router, React 19, TypeScript, PostgreSQL 16, Drizzle, Auth.js, next-intl, Zod และ sharp ไม่ได้สร้างแอปซ้อนหรือเปลี่ยนระบบยืนยันตัวตนเดิม ข้อมูลไทย/อังกฤษใช้ตารางแปล `*_i18n` ที่มีอยู่เดิม โดยหน้าเว็บหลักเป็นภาษาไทย

## เริ่มใช้งาน

ต้องมี Node.js 22+ และ pnpm 10.33.0

```bash
pnpm install --frozen-lockfile
cp .env.example .env
# แก้ DATABASE_URL, AUTH_SECRET และ MEDIA_DIR ให้ตรงกับเครื่อง
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Seed เพิ่มเพียง 4 หมวดเริ่มต้น ไม่เพิ่มสินค้าหรือข่าวสมมติ และไม่เขียนทับการแก้ไขของผู้ดูแล:

1. พวงหรีดแบ่งปัน
2. ไฟเบอร์กลาส และ ไม้
3. ดอกไม้ประดิษฐ์
4. เย็บปักถักร้อย

สร้างผู้ดูแลคนแรกด้วยรหัสผ่านที่ป้อนอย่างปลอดภัย (bash):

```bash
read -s -p 'Admin password: ' ADMIN_PASSWORD
export ADMIN_PASSWORD
pnpm admin:create admin@example.org "ผู้ดูแลระบบ" owner
unset ADMIN_PASSWORD
```

คำสั่งเดิมกับอีเมลที่มีอยู่จะตั้งรหัสผ่านใหม่และยกเลิกเซสชันเดิม ไม่มีบัญชีหรือรหัสผ่านเริ่มต้นที่ฝังอยู่ในโค้ด

ดู Docker, deployment, สำรองข้อมูล และการเปิดใช้งานที่ [SETUP.md](SETUP.md)

ดูแผนผังหน้าเว็บไซต์ CMS และขอบเขตงาน hero ที่พักไว้ที่ [docs/STRUCTURE.md](docs/STRUCTURE.md)

## ภาพและ scroll sequence

ตราหน่วยงานใช้ไฟล์ต้นฉบับ `public/brand/cida-logo.png` จากโครงการเดิม ไม่ได้วาดใหม่

**พักงาน cinematic hero ไว้ก่อนตามลำดับงานที่ตกลงกัน** หน้าแรกใช้ `VocationalHero` แบบภาพนิ่งจากโครงการเดิม ไม่มี canvas ไม่โหลดเฟรม และไม่ต้องใช้ `frames_150.zip` เพื่อพัฒนาโครงสร้างเว็บไซต์หรือ CMS ให้เสร็จ

เก็บ `ScrollSequence` และตัวนำเข้าไว้สำหรับงาน hero ในขั้นถัดไป เมื่อพร้อมทำส่วนนี้ ให้วางไฟล์จริงที่ `public/frames_150.zip` แล้วรัน:

```bash
pnpm frames:import
```

ตัวนำเข้าตรวจ `frame-001.png` ถึง `frame-150.png` ครบทุกภาพ แล้วสร้าง `public/frames/manifest.json` โดยรักษา PNG ต้นฉบับ การนำเข้ายังไม่เปิด animation อัตโนมัติ: ต้องเชื่อม `ScrollSequence` กลับเข้าหน้าแรกและตรวจภาพจริงในขั้นงาน hero ภาพนิ่งปัจจุบันมีคำกำกับว่าเป็นภาพประกอบแนวคิด ไม่ได้ใช้เป็นรูปสินค้าจริง

## คำสั่งตรวจสอบ

```bash
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

CI ตรวจชุดคำสั่งนี้พร้อม PostgreSQL และรัน migration/seed ซ้ำ การสร้าง production image ใช้ workflow **Release** แบบกดสั่งเอง โดยต้องตั้ง repository variable `SITE_URL` ก่อน ไม่มีการ deploy ไปยังโฮสต์อัตโนมัติ
